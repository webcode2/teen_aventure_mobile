## How to resume work

1. Read this ledger and `migration-status.json`.
2. Select the earliest unfinished work package below. Use `MIGRATION-QUEUE.md` for its exact missing endpoints and original source locations.
3. Read original route/service behavior, including permissions, DTOs, deletion state, privacy and concurrency requirements. Reimplement with bounded native Firestore queries and transactions; no full-collection Prisma emulation.
4. Add emulator integration cases, including unauthorized access and concurrent writes. Add/review production composite indexes. A passing emulator query does not prove the production index exists.
5. Run the isolated Firestore test configuration and backend typecheck. Do not run the SQL suite's reset hooks or seed the existing SQL database.
6. Run `cd backend && npm run migration:status`. This discovers original route modules from `index.ts`, compares them to the native factory's registered routes and automatically queues every absent endpoint. Requires the workspace admin TypeScript installation for offline AST parsing. `/api` and `/api/v1` aliases count once.
7. Update the evidence and partial-feature notes here. Mark a work package done only after behavioral parity, not just route registration. New original endpoints appear in the generated queue on the next refresh.

`migration-status.json` is machine-readable; `MIGRATION-QUEUE.md` is its generated missing-route checklist. Do not manually mark generated entries done: implementing a route removes it on refresh. Preserve remaining behavioral gaps here even when a route exists.
