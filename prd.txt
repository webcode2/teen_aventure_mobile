1. Product Overview

ASK Hub is a digital discipleship platform for children, teens, families and churches. The platform
supports structured Bible, prayer, devotional and engagement experiences while giving parents and
church leaders access only to information appropriate to their role.

The product supports local church ministry and is not intended to replace in-person ministry. Live
classes, general chat and unrestricted adult-to-child communication are outside the MVP scope.

2. Product Vision

 Help families support consistent faith engagement between Sundays.
 Provide age-appropriate Bible, prayer and devotional experiences.
 Give churches appropriate tools to organize classes and encourage participation.
 Keep family-owned information private while providing appropriate church-level visibility.
 Provide a scalable foundation for future administration, compliance, analytics and content

    capabilities.

7. MVP Data Lifecycle

 Deletion request immediately removes church-side visibility.
 0-30 days: recoverable.
 30-90 days: backend-only.
 90+ days: permanent purge according to the approved lifecycle.
 Safeguarding investigations may extend retention until the investigation closes.
 Retention periods are global product rules, not church-configurable settings.

8. MVP Technical Architecture

Recommended MVP architecture: a modular TypeScript backend rather than multiple microservices.
This keeps the initial system maintainable and cost-effective while preserving clear domain
boundaries for later extraction.
 Mobile: Flutter / Dart.
 Backend: TypeScript API.
 Database: PostgreSQL as the persistent source of truth.
 Object storage: media and file assets.
 Background workers: notifications, scheduled jobs, deletion processing and other asynchronous

    tasks.
 Cloudflare or equivalent: DNS, SSL, CDN/WAF where appropriate.

PostgreSQL remains the system of record. Redis is not part of this build.

Hosting & Infrastructure

The application will initially use a cost-optimized cloud infrastructure. Hosting will be configured to
minimize unnecessary recurring costs during the initial launch period. Actual infrastructure charges
depend on usage and the cloud provider's current pricing; no permanent free-tier guarantee is made.

Recommended MVP approach: TypeScript Cloud Functions/backend services, PostgreSQL as the
primary application database, and managed/object storage for media. Redis is not part of this build.

The existing Devotional and Bible-in-a-Year implementation currently uses Firestore only as content
storage. Since the new platform requires relational users, families, churches, classes, permissions,
activities and engagement data, PostgreSQL is recommended as the primary system of record.
Existing content may be migrated from Firestore into the consolidated architecture rather than
maintaining Firestore as a second application database.
