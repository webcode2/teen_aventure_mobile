# Android Play Store readiness audit — 18 October 2026

**Update after implementation:** Account-deletion source findings below are superseded by [the implemented lifecycle and verification report](../ops/account-deletion.md). Production deployment/scheduling still needs verification. Other submission findings remain applicable.

**Original audit verdict: not ready to submit.** Static source review and local builds do not replace Play Console declarations, internal testing, or physical-device verification.

## Submission blockers

1. **Upload signing and release artifact.** `mobile_/android/key.properties` is absent. The existing release APK uses `CN=Android Debug`; it must not be submitted. Release tasks now fail explicitly without upload signing. Restore/configure the correct upload key, build a signed AAB, and inspect that exact artifact. Preserve application ID `com.elasctroclud.teen_aventure`; confirm it before the first upload. Version is currently `1.0.0+1`; use an unused version code for every upload.
2. **Account deletion is incomplete.** Only parents have the identified in-app family-deletion action. Independent account holders need an account-deletion route too, plus an external public deletion-request URL. Family purge currently removes the Family while leaving the parent User identity; transition identities and retained records require an explicit retention/deletion design. The lifecycle worker can strand failed purges because later passes only process newly returned transitions. Implement identity deletion and retry handling with isolated database tests before claiming deletion compliance. Admin-only deletion does not substitute for self-service deletion.
3. **Privacy and Data safety are outdated.** The former checked-in disclosures describe an offline app without accounts. Actual functionality includes accounts, family/teen profiles, progress, group participation and push registration. The draft inventory in `data-safety.md` is a starting point, not approved Console answers. Publish accurate privacy/retention/deletion disclosures and verify the dashboard-configured legal links. Do not publish the old legal markdown unchanged.
4. **Audience declaration is unresolved.** Source supports child profiles ages 0–14 and independent teens 15–19, while listing copy says 13+ and excludes under-13 users. Resolve the product/store audience and assess Families requirements and all SDKs, including embedded video, against that audience.
5. **Reviewer access is unverified.** From this audit environment, the configured app host returned HTTP 403 for health/legal API checks; the production API health and public privacy page timed out. This does not prove a global outage, but public availability has not been established. Verify the intended release API, legal URLs, valid review credentials and account-role access from a clean external network. The source default selects the tunnel environment; explicitly provide the verified release endpoint.

## Fixes included in this audit

- Removed the release fallback to Android debug signing; release tasks require configured upload signing and an existing keystore.
- Moved optional push startup after the first frame, caught initialization failure, and coalesced concurrent startup calls so optional notification setup cannot block first render.
- Disabled Android backup and explicitly excluded app data from cloud backup and device transfer.
- Guarded account-deletion error-state updates when the screen has already been disposed.

## Local verification

- Flutter 3.47.4 / Dart 3.13.3; compile/target SDK 36; existing APK min SDK 24.
- Debug APK build passed with the current fixes, including the new backup XML resources.
- Release AAB build intentionally failed with the new missing-upload-signing message. No current signed AAB is available.
- Flutter test suite: all 86 tests passed on the final rerun after the source changes. `git diff --check` also passed.
- Flutter analysis: no errors, one pre-existing unused `_advanceCursor` warning and 73 informational findings. Analysis is not clean.
- Existing release APK: version 1.0.0 / code 1, 82,726,118 bytes; SHA-256 `bc7bf51012d3ef41dc76209e84c93cfc63695b70be403591c366d1a40c9208ba`.
- Existing APK passed `zipalign -c -P 16 4`. All 14 inspected 64-bit native ELF libraries had load-segment alignment of at least 16 KB. These checks apply to the existing artifact, not an unbuilt release AAB, and do not establish execution on a 16 KB device.
- Existing APK permissions: internet, camera, notifications, network state, wake lock, FCM receive and the application receiver permission. No advertising ID, location, microphone or broad storage permission was observed. Camera features are optional.
- Release source disables cleartext traffic; minification and resource shrinking are enabled.

## Remaining hardening and device checks

- ApiClient duplicates the authentication token in plaintext SharedPreferences even though AuthService uses secure storage. Remove the duplicate and migrate existing installations safely.
- Verify cold start/offline behavior: GoogleFonts uses runtime fetching and no bundled font files were found.
- Profile scrolling, background rendering, memory, thermal behavior and battery use on a small low-memory phone. Prior user screenshots show rendering corruption and overheating; a successful compile does not resolve those observations.
- Test Android 15/16 edge-to-edge insets, navigation/back handling, large text, keyboard, rotation, denied camera/notification access, deep links, webview failure/retry, and interrupted account deletion.
- Test push delivery and notification permission on a physical device with production Firebase configuration.
- Gradle warns that device_info_plus, mobile_scanner and share_plus still apply Kotlin Gradle Plugin; monitor built-in Kotlin compatibility before future Flutter upgrades.
- Complete Play Console app access, content rating, audience, Data safety, privacy/deletion URLs and any account-specific testing requirements. Console access was not part of this local audit.
