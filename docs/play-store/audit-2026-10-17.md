# Play Store readiness audit — 17 October 2026

Verdict: **not ready for submission**. This is a source/configuration audit with Flutter analysis and tests, not a device certification or Play Console review. Existing workspace changes were preserved. No application fixes were made.

## Confirmed blockers

1. **Release falls back to debug signing.** `mobile_/android/app/build.gradle.kts:47–51` chooses the debug key when `android/key.properties` is missing; that file is absent in this checkout. Configure the upload key securely and make release builds fail if signing is missing. Verify the final AAB certificate against the intended Play upload certificate. No private keys were opened.

2. **Privacy and Data safety disclosures are materially obsolete.** `mobile_/lib/screens/account/legal_screen.dart:36` and `docs/legal/privacy-policy.md` say there are no online accounts and progress stays locally; `docs/play-store/data-safety.md` says personal information is not collected and deletion is not applicable. `AuthService.registerParent/registerTeen` send names, email, birth year and credentials; push registration sends FCM and device metadata, and activity is synchronized. Rewrite in-app/public policies and Data safety from an actual data inventory, including purposes, recipients, retention, deletion, children, and SDK behavior. Assess sensitive religious information from ministry affiliation/activity. Do not equate first-party collection with third-party sharing; classify each correctly.

3. **Self-registering users lack complete account deletion.** `mobile_/lib/screens/account/account_screen.dart:272` exposes only parent family deletion. Standalone teen accounts and adults without an owned family lack an equivalent personal-account path. The auth routes expose device deletion, not personal-account deletion. No public account-deletion request page was identified in the inspected web routes. Supply in-app deletion for supported account types and a working external deletion-request resource for Play Console; disclose any legitimate retention exceptions.

4. **Family purge does not purge the adult identity.** `backend/src/workers/lifecycle.worker.ts:50` deletes only Family. `backend/prisma/schema.prisma` defines Family.owner as a reference to User; deleting Family does not delete User. Adult name/email/password hash and associated user records therefore survive this flow. Define family removal separately from personal-account deletion and explicitly delete/anonymize the relevant identity and associated data. Handle guardians/shared ownership and safeguarding exceptions deliberately.

5. **Failed permanent purges are stranded.** `runLifecyclePass` transitions a family to `purge_pending` once; `startLifecycleWorker` purges only families returned in that pass's transitions. If deletion fails or the process stops after the transition, later passes omit that already-pending family. Retry all eligible pending purges independently of newly created transitions, rechecking retention holds, and monitor failures. Verify this against an isolated test database.

6. **Audience declarations contradict child functionality.** Listing, legal text, and console checklist say 13+ and exclude under-13s. `mobile_/lib/family/family_account_rules.dart:4` supports ages 0–19, and parent flows create child profiles and enable child play. Decide the intended distribution audience, then align implementation, listing, terms, consent, and Play declarations. If children are included, assess every SDK and embedded YouTube experience against Families requirements. This audit does not establish children's privacy-law compliance.

## Release risks and unverified gates

- **Backend selection:** `mobile_/lib/config/api_config.dart:10` defaults to the Cloudflare tunnel, while a separate production API is defined. Release configuration accepts an arbitrary API override. Explicitly select the supported production endpoint and verify availability, TLS, backups, email delivery, rate limits, and reviewer access. Tunnel use alone is not evidence of a policy violation or outage.
- **Startup permissions:** Service initialization awaits Firebase and notification permission before `runApp` (`service_locator.dart:50`, `push_service_io.dart:28`). Move optional push initialization after the first frame and request permission with context; verify cold start with denied permission, no connectivity, and unavailable Play Services. A crash was not reproduced.
- **No current AAB verified:** No APK/AAB file was found under the inspected build tree; old build intermediates are not release evidence. Produce a signed release AAB and inspect its merged manifest, dependencies, certificate, version code, architectures and native library alignment. Verify 16 KB compatibility on the actual artifact and a 16 KB device/emulator.
- **Stale operator instructions:** `docs/play-store/console-checklist.md` uses `mobile/`, points at removed sample-content paths, and describes an offline release fallback that the current live-only auth app does not provide. Replace it with the actual build and deployment procedure.
- **Console-only checks remain:** Verify developer account/app registration, app access instructions and reviewer credentials, target audience, IARC, privacy/deletion URLs, Data safety, listing assets, and any account-specific production testing requirement. Console access was not available for this audit.
- **Device acceptance remains:** Test release install/upgrade, adult and teen registration/login, parent-child switching, password recovery, slow/offline API, video playback, Objective Quiz, crossword and matching games, camera denied/retry, notifications, logout, and deletion across account roles. Check small screens, large text, Android back navigation, Android 16 insets and process restoration. No live accounts were created/deleted.
